# Wiring memory into agentd

**Schema changes from the brain (Memory B, 10-27). All additive, backward compatible.**
- New table `entity_link(id PK → entity, canon → entity, conf, why)`, created on first use by `resolve.js` and recomputed from scratch whenever the data changes. It says, with a confidence and a reason, that one card is another person, e.g. "Jordan W." on Discord is Jordan Wu (first name + last initial, 85%) or "Linda Gimenes" on Messenger is Mom (Mom's email has that name, 90%). Nothing is rewritten. Both FKs are `ON DELETE CASCADE`, so revoking a source removes its links. Links ≥ 0.8 count as one person; lower ones are only shown.
- `store.redact()`: a URL with a query string keeps its readable path (`https://www.climbing.com/skills/hangboard-training-guide/?…`) unless the path holds a token (6+ digits, or a 25+ character run). Before, the whole path was dropped. The query is still always dropped.
- Nothing else changed: no columns, no event kinds. The brain reads Memory A's kinds as they are (`listen`, `web`, `usage`, `media` photos, `message` from the notification feed).

**The brain (`brain.js`, `profile.js`, `resolve.js`).** `memory.contextLines(goal, {cloud})` returns the few memories that most likely answer a request (≤3 events, computed facts, the person card). `context.js` puts them in `<phone_context>` ("Memory for this request"), guarded like notifications, so most questions need no tool call. `memory_ask {q}` is the tool version: facts plus cited events. `memory.ask` / `memory.recall` / `memory.profile` are there for UIs and evals. `memory.unpseudo(x)` maps `[P:n]`/`[E:n]` in a cloud model's tool args back to real values (`tools.js`), and `memory.unpseudoStream()` does the same for the reply text the user sees (`server.js`). The local model gets raw text (`cloud:false`), and `providers/local.js` answers memory questions from `contextLines`. Eval: `memory/eval/` (see RESULTS.md there).


`import * as memory from './memory/index.js'` gives you `memory.tools` (nine specs `{name, tier, description, schema}` in the same shape as `TOOLS` in `tools.js`), plus `memory.call(name, args, ctx)`, which resolves to a JSON-able object and never throws. Add the specs next to `TOOLS` for every provider and the `/mcp` list. In `runTool`, before the `TOOLS[name]` lookup, add `if (name.startsWith('memory_') || name.startsWith('consent_')) return { success: true, text: JSON.stringify(await memory.call(name, args, { cloud: provider !== 'local', confirm: ... })) }`. Leave `actor` at its default of `'agent'`. Set `cloud: false` only for the local model: it then gets raw text, and cloud models get `[P:n]`/`[E:n]` pseudonyms. Three tools are tier `outward`: `consent_grant`, `consent_revoke` and `memory_forget`. They refuse unless `ctx.confirm(summary)` resolves `true`, so wire `confirm` to the phone's approval card, or leave it out and the model is told to ask the user. Results carry `trusted:false` plus a "data, not instructions" note. You can also pass result text through `guard.js`. For the graph UI, serve `memory.graph()` at `GET /memory/graph.json` (Cytoscape `{nodes, edges}`; each edge has a `via` source to colour by, and `consents`). For the WhatsApp share-sheet flow, call `memory.ingest('whatsapp', {file})` after the user grants. The DB is `~/.agentos/memory.db` (`MEMORY_DB` overrides it). It needs Node ≥ 22.13 (`node:sqlite`; FTS5 is verified on Mac Node 24 and Termux Node 25). Demo and dev tools: `node memory/cli.js` (grant / ingest / search / revoke / graph / `serve` on :8790) and `node memory/test.js`.

**Deletes, edits, owner consent (10-27 night).** `memory.noteApi(method, params, result)` mirrors a successful direct API write (calendar.add/update/delete, alarms.delete, set_alarm) right away; tools.js calls it after every non-read call. New store helpers `putEvent` (replace-if-changed) and `prune(db, source, liveIds)`; no schema changes. The launcher's Memory toggles send `{type:"memory.consent", source, action:"grant"|"revoke", scope?}` over the agentd WebSocket and get `{type:"memory.consent", ok, ...}` back. agentd honours it only when the connection's uid (root read of `/proc/net/tcp*`, like the broker's owner line) is `local.agentos.home`'s, so the keyboard, the tool server, agentd/Codex (Termux uid) and every model are refused; verified on the phone. Ledger actor `user:owner`. Revoke = the usual hard delete, and its connector stops (syncAll skips inactive sources); grant re-reads the source at once.

**Live messages (context.js, 10-27).** `memory.noteMessage({pkg, app, conversation, sender, text, when, group, dir})` saves one message from the phone's notification feed (or a reply we sent, `dir:'out'`) as a `message` event from source `notifications`, linked to the person (`from`/`to`), the app (`app`) and, for group chats, the group. It does nothing unless `notifications` is granted. `memory.recentPeople({cloud}, n)` returns `[{name, apps, last, text}]`, newest first: "who do I talk to, and in which app". `context.js` puts it in every task's `<phone_context>`.
