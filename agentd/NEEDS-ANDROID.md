# Requests for the android/ owner (from agentd)

None of these block the demo. Done since the first version: taint carry-over and the lease card (thanks).

1. **Approval escalation for the reviewer: DONE (2026-10-27).** `approval.escalate {approval_id, to:"fingerprint", rationale}` (see android/README.md). `reviewer.js` calls it on a `fingerprint` verdict, and skips the re-sent `approval.shown` (`escalated: true`). Tested on the phone in a real turn.
   - agentd matches the shipped API (Broker.java/Events.java): `hello` on connect, `approval.confirm` with `voice`+`utterance` or `reviewer`+`rationale`, `approval.deny`, and `allowed_channels` to tell ordinary from fingerprint-only approvals.
2. **The launcher WebView's token.** agentd writes its WebSocket token to `/data/data/local.agentos/files/agentd.token` (owner = app uid, mode 600, app's SELinux label) at start-up. The launcher/island WebView can read it there and connect with the `agentos.bearer.<token>` subprotocol. The same goes for `local.agentos.keys`.
3. **Steps carry over between tasks: FIXED (integration, 2026-10-27, Broker.start).** A new task after the old one stopped keeps the taint but starts at step 0 (`if (same && lease == null) l.h.steps = 0`). Widening a live task keeps the count. Verified: back-to-back tasks report `carried_over:true, steps:0`.
4. **Prompt Guard false positives: FIXED (speed track, 2026-10-27, PromptGuard.java).** Text-less button labels under 8 tokens aren't scored ("History mode off" scored 0.98 and flagged every Calculator task), and the joined whole-screen text flags only at ≥ 0.9 (Calculator's first run joined to 0.57). The Pigeon canary still flags at 0.967. Still open: each read spends 0.2–0.6 s in PG; intermediate reads inside one `act` batch could skip it.
5. **Direct intents: DONE (speed track, 2026-10-27).** `intent {kind: alarm|timer|search, ...}` (Actions.intent, allow-list only, no URLs/SMS/call intents), same lease/tier/audit path as a tap; a search is T2 and goes through the P3 leak check. agentd exposes it as `set_alarm`, `set_timer`, `web_search`.
6. **Settle is often the full 2 s.** Clock/Chrome keep emitting events, so `settle()` rarely sees 300 ms of quiet. Ignoring `TYPE_WINDOW_CONTENT_CHANGED` from views outside the active window, or capping at ~1 s after the first event, would save ~1 s per action.
7. **Lease card policy: CHANGED (integration, 2026-10-27, Broker.start + tools.js).** Before, every voice/typed task waited for an "Allow agent in Clock?" tap, and with nobody at the phone it failed after 60 s ("access approval timed out"; the bench hid this with `require_user_lease:false`). The card asked the user to repeat what they had just said. Now **the user's own request is the grant**: agentd sends `user_asked:true` on `task.start` for turns that come from the user's words (launcher, voice workers, cli; not reply-rule turns), and the broker skips the card when all of these hold:
   - the caller is agentd (`lease_callers`, default Termux), so no other program can claim it;
   - no app is sensitive: money, installs, passwords (`bank|pay|wallet|finance|credit|crypto|trading|broker|vending|packageinstaller|password|vault|…`). These still get the card (tested: "Open the Play Store" → card);
   - the request doesn't widen a **live** task that Prompt Guard flagged (an injected agent reaching for more apps). A new request after a flagged task is the user's again, but its sends still need a person (the existing 10-min flag rule).
   Why this is enough: the lease only says *which apps*. Each action still goes through tiers, Rule of Two, the reviewer and the audit log, and fingerprint stays on money/installs/passwords. `require_user_lease:false` still turns the card off everywhere. The audit's `task.start` entry has `by_request:true|false`.
8. **Prompt Guard false positives seen in real apps (open).** Clock's banner "Alarm volume is low and you might not hear it" scores 0.98 (fixed on stage by setting the alarm volume to 6/7, which hides the banner), and Slack's "Having trouble? Reset your password" flags on every read. One flag makes every send in the next 10 min need a person, so these cost demo friction. Ideas: skip the app's own static strings (same text seen on every launch), or need 0.99 for nodes under ~12 tokens.
