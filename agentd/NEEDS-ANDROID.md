# Requests for the android/ owner (from agentd)

None of these block the demo. Done since the first version: taint carry-over and the lease card (thanks).

1. **Approval escalation for the reviewer: DONE (2026-10-27).** `approval.escalate {approval_id, to:"fingerprint", rationale}` (see android/README.md). `reviewer.js` calls it on a `fingerprint` verdict, and skips the re-sent `approval.shown` (`escalated: true`). Tested on the phone in a real turn.
   - agentd matches the shipped API (Broker.java/Events.java): `hello` on connect, `approval.confirm` with `voice`+`utterance` or `reviewer`+`rationale`, `approval.deny`, and `allowed_channels` to tell ordinary from fingerprint-only approvals.
2. **The launcher WebView's token.** agentd writes its WebSocket token to `/data/data/local.agentos/files/agentd.token` (owner = app uid, mode 600, app's SELinux label) at start-up. The launcher/island WebView can read it there and connect with the `agentos.bearer.<token>` subprotocol. The same goes for `local.agentos.keys`.
3. **Steps carry over between tasks (blocks back-to-back demo tasks).** `start()` keeps the same caller's `History` for 10 min, including `steps`, so after ~40 total actions every new task fails with "task reached max_steps 40". Keep the taint, reset the count: in `start()`, after building the Lease, `if (same) l.h.steps = 0;`. (Found by the speed bench, 2026-10-27; the bench works around it with a throwaway lease from adb.)
4. **Prompt Guard false positives: FIXED (speed track, 2026-10-27, PromptGuard.java).** Text-less button labels under 8 tokens aren't scored ("History mode off" scored 0.98 and flagged every Calculator task), and the joined whole-screen text flags only at ≥ 0.9 (Calculator's first run joined to 0.57). The Pigeon canary still flags at 0.967. Still open: each read spends 0.2–0.6 s in PG; intermediate reads inside one `act` batch could skip it.
5. **Direct intents: DONE (speed track, 2026-10-27).** `intent {kind: alarm|timer|search, ...}` (Actions.intent, allow-list only, no URLs/SMS/call intents), same lease/tier/audit path as a tap; a search is T2 and goes through the P3 leak check. agentd exposes it as `set_alarm`, `set_timer`, `web_search`.
6. **Settle is often the full 2 s.** Clock/Chrome keep emitting events, so `settle()` rarely sees 300 ms of quiet. Ignoring `TYPE_WINDOW_CONTENT_CHANGED` from views outside the active window, or capping at ~1 s after the first event, would save ~1 s per action.
